联调报错，别再靠截图。

SnapRequest 自动捕获失败的接口请求，一键生成分享链接。后端打开即可用原始认证信息重放， 并把处理结果实时回传给你。

为什么做这个

把「失败的那一次请求」，完整地交给后端。

联调时接口报错，往往靠截图或口述。请求头、参数、认证信息、响应体在传递中大量丢失， 后端难以复现，只能反复来回问。SnapRequest 解决的就是这段沟通成本。

以前

  • 截图/复制一段，关键信息丢失
  • 认证信息（Cookie / Token）说不清，后端无法复现
  • 「你那边好了吗？」——没有回执
  • 反复沟通，效率低

用 SnapRequest

  • 一条链接带走完整请求 + 响应
  • 认证信息加密随链接传递，后端一键重放
  • 后端标记「已解决 / 仍报错」，你这边实时可见
  • 一次说清，闭环处理
核心能力

为联调而生的六个能力

⚡

双通道捕获

后台静默记录失败请求；也可在 DevTools 的 SnapRequest 面板里主动挑选、右键分享。

🎯

精准过滤

按 URL、方法、状态码、资源类型过滤，只保留有用的请求，避免噪音。

🔗

一键分享

生成短链接，可设置有效期与最大访问次数，链接随时可撤销。

🔒

认证信息加密

Cookie / Token 以 AES-GCM 加密存储，页面不展示明文，仅重放时在服务端解密。

🔁

一键重放

后端用原始认证信息重发请求，自动并排对比「原始响应 / 重放响应」并给出判断提示。

✅

状态闭环

后端标记处理结果并留备注，状态实时同步回扩展侧边栏。

怎么使用

六步跑通闭环

1
下载并解压扩展 点下方「下载扩展」得到 zip，解压到任意目录。
2
加载到浏览器 打开 chrome://extensions → 右上角开启「开发者模式」→ 「加载已解压的扩展程序」→ 选择解压后的文件夹。
3
触发一次失败请求 在页面上操作，让接口报 4xx/5xx；或打开 DevTools 的 SnapRequest 面板主动挑选。
4
分享给后端 点扩展图标打开侧边栏 → 选中请求 → 「分享给后端」，链接自动复制。
5
后端查看并重放 打开链接查看请求详情 → 点「重放」对比响应 → 标记「已解决 / 仍报错 / 需更多信息」。
6
你实时收到结果 侧边栏「最近分享」的状态会自动更新，闭环完成。
